# Indicator Full Port — Design

**Date:** 2026-08-25
**Goal:** Bring the backend indicator registry to full parity with openalgo-charts-master (~70 Tier-1 indicators), with every port verified by executing the actual TypeScript source.

## Problem

The v4 backend registry (`trading/src/tradex_trading/analytics/indicators.py`) exposes 11 indicators. Audit against `/Users/apple/Downloads/openalgo-charts-master` found:

1. **MACD is non-standard** — computes EMA13 − EMA26 (`period//2` hack), emits only the MACD line. Reference: EMA12 − EMA26 + signal (EMA9) + histogram.
2. **Stochastic %K is unsmoothed** — reference applies smoothK=3 SMA before %D.
3. **EMA seeding convention differs** — backend seeds from SMA of first window; reference seeds from `values[0]`.
4. **~59 Tier-1 indicators missing** from the registry.

## Decisions (user-approved)

- **Scope:** full port of all computable Tier-1 indicators (Seasonality excluded — it is a UI table widget, not a series).
- **Parity:** exact. Adopt openalgo-charts conventions — EMA seeded from `values[0]`, same defaults and param names, `None` padding matching source NaN warmup regions exactly.
- **Verification:** golden fixtures generated by running the actual TS indicator code on shared fixture candles; Python ports must match to 1e-9.

## Architecture

```
scripts/generate_goldens.mjs                       # one-time Node harness
trading/tests/analytics/goldens/*.json             # committed goldens {id, params, expected plots}
trading/src/tradex_trading/analytics/indicators.py # all ports land here (existing single-file pattern)
trading/tests/analytics/test_golden_parity.py      # parametrized parity tests
```

No new modules or abstraction layers. The existing `_REGISTRY` / `IndicatorSpec` / `compute_indicator` seam is the entire integration surface; the frontend picks up new registry entries automatically (covered by the existing seam test).

### Golden harness

- `scripts/generate_goldens.mjs` imports indicator descriptors from the openalgo-charts package (`src/indicators/*`), runs each descriptor's `calc()` on a deterministic fixture candle set, writes JSON per indicator id.
- Fixture set: ~300 synthetic 1-minute bars covering steady trend, chop, flat runs, zero-volume bars, gap bars, plus a session boundary for anchored indicators.
- Goldens are regenerated only when intentionally re-baselining; they are committed test data.

## Conventions

- `ema()` changes seed from SMA-of-window to `values[0]`; downstream users re-verified against updated goldens. Bollinger (SMA-based) unaffected; Supertrend's Wilder ATR keeps its own seeding per its reference implementation.
- Param names and defaults copied verbatim from the reference `inputs`.
- Warmup regions are bar-for-bar aligned: `None` where the source produces NaN.
- Fail-loud registry contract unchanged: unknown params/ids raise `ValueError`.

## Testing

- `test_golden_parity.py`: parametrized over all goldens; `pytest.approx(abs=1e-9)` on values and exact alignment of `None` positions.
- Existing 151 analytics/interface tests stay green; MACD/stochastic assertions updated where goldens legitimately change.
- Each batch lands with its goldens committed and the full suite green before the next batch starts.

## Out of scope

- Strategies/backtest/scanner logic (correctly lives in the backend already; chart library has none).
- Seasonality table widget.
- Frontend changes (Tier-2 wiring is discovery-driven; zero frontend edits required).
