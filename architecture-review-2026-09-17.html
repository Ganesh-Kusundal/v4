Problem

engine.py absorbs fee calculation, fill dedup, kill switch, and CQRS dispatch into one 974-line class. The sibling fees.py has a FeeCalculator whose constructor parameters are accepted but never consulted — the engine inlines its own fee math instead. The execution/__init__.py re-exports 30+ symbols, hiding which submodule owns what.

Solution

Make engine.py a thin orchestrator: delegate fee calculation to fees.py (activate the constructor params), extract fill dedup into idempotency.py, extract kill switch into its own module. Collapse __init__.py to re-export only the public intake interface.

Wins

  • locality: fee bugs concentrate in fees.py, not split across two modules
  • leverage: one intake interface, three testable adapters behind seams
  • depth: engine interface shrinks; implementation absorbs the wrappers
  • Tests hit one interface per concern, not the god-class
  • Delete the misleading FeeCalculator dead params

Unify the Datalake dual sync and fetch paths

Strong in-process
datalake/historical_sync.py (217 LOC) — SyncOrchestrator
datalake/simple_sync.py (186 LOC) — "ponytail edition"
datalake/parallel_fetcher.py (702 LOC) — multi-broker, auto-chunk
datalake/simple_fetcher.py (152 LOC) — basic ThreadPoolExecutor

Before — two parallel hierarchies

historical_sync.py — SyncOrchestrator + SyncResult + series_to_frame()
simple_sync.py — direct loop + SyncResult (dup) + series_to_frame() (dup)
parallel_fetcher.py — multi-broker, auto-chunk, K-failure, clipped-tail
simple_fetcher.py — ThreadPoolExecutor subset

Two sync paths, two fetch paths. Same domain, duplicated types.

After — one deep module per concern

sync.py — single sync entry point
delegates to ParallelFetcher, owns SyncResult + series_to_frame()
parallel_fetcher.py — sole fetch implementation
simple_fetcher.py deleted; call sites use the deep module

One seam per concern. Delete ~340 LOC of duplicated types.

Problem

Two sync implementations define the same SyncResult and series_to_frame(). Two fetcher implementations cover overlapping ground — the 702-line parallel fetcher is a strict superset of the 152-line simple fetcher. Neither delegates to the other. Call sites must choose which path to use, and the wrong choice silently drops multi-broker routing or clipped-tail repair.

Solution

Delete simple_sync.py and simple_fetcher.py. Route all callers through historical_sync.py (renamed to sync.py) which delegates fetching to parallel_fetcher.py. One interface, one place to test.

Wins

  • locality: sync bugs concentrate in one module
  • leverage: one fetch interface, all call sites use the same path
  • Delete ~340 LOC of duplicated types and conversion logic
  • Multi-broker routing and clipped-tail repair become the only path — no silent degradation

Problem

The common/ package contains broker-specific rate tables, auth flow factories, and capability functions — all keyed by broker name. Adding a third broker requires editing the "generic" infrastructure. The seam between common and adapter-specific is leaky: common knows about Dhan and Upstox by name.

Solution

Extract rate tables to dhan/rate_table.py and upstox/rate_table.py. Move auth flow factories to per-broker modules. Common keeps only the generic primitives (TokenBucket, CircuitBreaker, TOTP). Two adapters justify the seam: each broker brings its own config.

Wins

  • locality: adding a broker touches only its own directory
  • leverage: common primitives serve N brokers without modification
  • common/resilience.py drops from 1,249 to ~600 LOC
  • Auth flow changes don't risk breaking other brokers

Problem

PaperBroker (845 lines) is a standalone class that manually re-implements every method of the BrokerAdapter protocol. Bug fixes to BaseBroker's lifecycle, pass-through wall, or instrument loading don't propagate. The fill engine, cash ledger, and tape seeding are mixed with broker infrastructure in one monolith.

Solution

Make PaperBroker extend BaseBroker. Override only the adapter-specific methods (fill engine, cash ledger, market simulation). Inherit lifecycle, instrument loading, order gates, and stream management. Extract the simulation logic into focused modules.

Wins

  • locality: BaseBroker bug fixes propagate to Paper automatically
  • leverage: one lifecycle path, one instrument loading path
  • Parity tests (backtest=paper=live) gain confidence from shared infrastructure
  • Paper simulation logic becomes independently testable

One interface. Fill + re-mark is atomic. No forgotten steps.

Problem

Domain's position_math.py has zero domain-level tests. The trading layer's 18-line re-export shim adds nothing. The real bugs hide in orchestration: apply_fill wipes mark_price and unrealized_pnl on every fill — if the caller forgets to re-mark, positions show zero P&L. Five modules share this concern; none owns it.

Solution

Create a PositionAccountant in trading that wraps the domain pure functions and makes fill+re-mark atomic. Delete the 18-line re-export shim. Add domain-level property-based tests for apply_fill invariants.

Wins

  • locality: position bugs concentrate in one module
  • depth: small interface (fill/split/mark/equity), rich implementation
  • Fill + re-mark becomes atomic — no forgotten steps
  • Domain pure functions finally get property-based tests
  • Delete the 18-line re-export shim

Route shutdown through the ShutdownCoordinator — eliminate the monkey-patch

Speculative in-process
trading/.../runtime/startup.py (695 LOC) — monkey-patches session.stop
trading/.../runtime/shutdown.py (70 LOC) — ShutdownCoordinator (bypassed)
trading/.../sdk/session.py (425 LOC) — TradingSession

Before — monkey-patch bypasses coordinator

After — coordinator owns the sequence

sequenceDiagram
  participant Boot as startup.boot()
  participant Sess as TradingSession
  participant Coord as ShutdownCoordinator
  participant Lock as WriterLock
  Boot->>Sess: create session
  Boot->>Coord: register("writer_lock", priority=10)
  Boot->>Coord: register("session.stop", priority=20)
  Note over Boot,Lock: At shutdown:
  Coord->>Lock: release (priority 10)
  Coord->>Sess: stop (priority 20)
  Note over Coord: ordered, visible,
testable

Problem

startup.py monkey-patches session.stop to release the writer lock, bypassing the ShutdownCoordinator that was specifically designed for ordered shutdown. The shutdown sequence is invisible — you can't see what runs in what order without reading the monkey-patch.

Solution

Register the writer lock release and session stop as named entries in the ShutdownCoordinator with explicit priorities. Remove the monkey-patch. The coordinator becomes the single authority for shutdown ordering.

Wins

  • locality: shutdown logic lives in one module, not split between startup and session
  • leverage: adding a shutdown step = one register() call
  • Shutdown ordering becomes testable through the coordinator interface
  • Delete the monkey-patch and the module-global _ACTIVE_WRITER_LOCK
